先講白話，別抱太大期望。vercel.app 和 zeabur.app 都已經被 F-ISAC 擋掉了，代表這波掃得很乾淨。Koyeb 只是「比較冷門、可能還沒進名單」，我估成功率 30–40%。這份手冊做完約 1.5 小時工，就算最後行內連不進去，也等於幫我們確認「免費雲子網域這條路走不通」，下一步就直接走白名單申請 + 綁自有網域（治本）。不算白做。

0

開始前，先備齊這四樣

缺一樣就會中途卡住，先確認手邊都有。

  • 能登入 GitHub（就是 studio-yang 這個帳號，程式放在它底下）
  • 能打開 Vercel 後台 — 待會要從這裡把環境變數一個個抄過去
  • 能打開 Google Cloud Console — Drive 上傳的 OAuth 設定要加一條新網址
  • 一支手機，可以開 4G 熱點 — 部署完先用手機（非行內網路）自測功能
1

註冊 Koyeb，建立服務

用 GitHub 登入最省事，它會自動抓到你的程式庫。

  1. 開 app.koyeb.com，點「Sign up with GitHub」用 GitHub 登入，之後選 repo 不用再授權第二次。
  2. 進到主畫面後，點「Create Web Service」若看到的是「Create Service」也一樣，選 Web Service。
  3. 部署來源選「GitHub」另一個選項是 Docker image，我們不用。
  4. 第一次會要你安裝 Koyeb 的 GitHub App跳出 GitHub 授權頁時，選「Only select repositories」→ 勾 studio-yang/fileuploader → Install。只給這一個 repo 權限就好。
  5. 回到 Koyeb，選 repository：fileuploader，branch：main
  6. Builder 這格請確認顯示「Buildpack」Koyeb 會自動認出這是 Next.js。若之後 build 失敗，再改用 Dockerfile（見文末排錯）。
⚠️

務必檢查 Builder 那格。repo 裡現在放了一份備用 Dockerfile，Koyeb 有可能自動把 Builder 切成「Dockerfile」。我們這輪要先試 Buildpack（比較單純），所以請手動確認它顯示的是 Buildpack。兩種都能跑，但先照計畫走 Buildpack，卡住再切 Dockerfile。

💡

Instance / Region 這樣選：Instance 選 Free（512MB）。Region 免費方案只有兩個：Washington, D.C. 和 Frankfurt — 選跟你 Upstash Redis 同一區或最近的那個，登入才不會因為跨海變慢。不確定 Redis 在哪區就先選 Washington, D.C.。

🔌

Port 不用改。Koyeb 會自動給程式一個 PORT，Next.js 會自己讀，維持預設即可。Health check path 填 /。

2

填環境變數

在建立畫面往下捲到「Environment variables」，一條一條加。值全部從 Vercel 後台抄。

變數名稱值 / 來源必填
AUTH_SECRET 從 Vercel 抄，務必用同一組，否則已登入的人 session 全失效 必填
REDIS_URL 從 Vercel 抄（rediss://… 開頭） 必填
BREVO_API_KEY 從 Vercel 抄（寄 OTP 信用） 必填
BREVO_SENDER alan0109@mail2000.com.tw 必填
OTP_RECIPIENT alan0109@mail2000.com.tw 必填
GOOGLE_* Vercel 上所有 GOOGLE_ 開頭的變數全部抄過來（Client ID / Secret / refresh token 那組，Drive 上傳用） 必填
NEXT_PUBLIC_APP_URL 先跳過這條！它的值是 Koyeb 網址，但要部署完才知道。Phase 3 再回來補。 稍後
📋

怎麼從 Vercel 抄？Vercel 後台 → 選 fileuploader 專案 → Settings → Environment Variables。每條點眼睛圖示顯示明文，複製貼到 Koyeb 對應欄位。Koyeb 環境變數區也有「Bulk edit」可一次貼多條，格式是 KEY=value 每行一條。

🔑

怎麼分辨哪些是 GOOGLE_ 變數？在 Vercel 環境變數清單裡，名字開頭是 GOOGLE_ 的全部都要（通常有 client id、client secret、refresh token、folder id 之類）。寧可多抄，不要漏。

3

首次部署 → 拿網址 → 回填最後一條變數

這裡有個「先有雞還是先有蛋」的小關卡，照順序做就好。

  1. 幫服務取個名字（App name）例如 chb-fileflow。這個名字會變成你的網址一部分。
  2. 點「Deploy」，等 build 跑完第一次約 3–6 分鐘。畫面會滾動 build log，看到 green / Healthy 就成功。
  3. 複製 Koyeb 給你的公開網址長得像下面這樣（實際字尾不同）： https://chb-fileflow-xxxx.koyeb.app
  4. 回到 Settings → Environment variables，新增 NEXT_PUBLIC_APP_URL值就填你上一步複製到的完整網址（含 https://，結尾不要斜線）。
  5. 存檔後點「Redeploy」讓新變數生效封鎖警示信裡的按鈕連結要靠這條變數才會指向 Koyeb，一定要補。
✅

為什麼要分兩次？因為網址是 Koyeb 部署後才生成的，沒辦法事先知道。先部署拿到網址、再回填、再重新部署，這是正常流程，不是你做錯。

4

Google OAuth 加一條重新導向網址

不加這步，登入沒問題，但 Drive 上傳會噴 401。

  1. 開 Google Cloud Console → Credentials
  2. 點開你現在在用的 OAuth 2.0 Client ID就是 Drive 上傳用的那個。
  3. 在「授權的重新導向 URI」按「+ 新增 URI」，貼上： https://（你的 Koyeb 網址）/api/upload/gdrive-token
  4. 存檔。舊的 Vercel 那條不要刪兩邊並存，這樣 Vercel 舊站還能當備援。
⏳

Google 設定有時要幾分鐘才生效。如果剛加完馬上測上傳還是 401，等 5 分鐘再試一次。

5

先用手機 4G 自測（不要用行內網路）

這步是確認「功能本身正常」，跟行內封鎖無關，所以用你自己的網路測。

  1. 手機開 4G / 熱點，開 你的Koyeb網址/login
  2. 輸入 email → 收得到 OTP 驗證碼收得到信 = Brevo、Redis 都通了。
  3. 輸入驗證碼登入成功
  4. 傳一個小檔案，確認上傳到 Drive、清單看得到上傳成功 = Google OAuth 那條有生效。
🎯

四項都過，代表整套系統在 Koyeb 上是活的。接下來才是真正的考驗 —— 明天在行內測。

6

關鍵驗證：明天，在行內電腦

這一步決定這整條路成不成。務必用行內網路的電腦測。

在行內電腦的瀏覽器開：

https://（你的 Koyeb 網址）/login

卡住了？對照這裡

  1. Build 失敗（Buildpack 認不出）repo 裡已經備好 Dockerfile，直接到服務設定把 Builder 切成 Dockerfile → Save → 重跑即可，不用等我。
  2. 網頁開得出來但一直 502 / 轉圈通常是 port 問題。到服務設定確認 Exposed port 用的是 Koyeb 預設值、Health check path 是 /。
  3. 登入收不到 OTP 信先檢查 BREVO_API_KEY、REDIS_URL 有沒有抄錯或漏抄。
  4. 能登入但上傳噴 401Google OAuth 重新導向 URI 沒加對，或還沒生效。回 Phase 4 核對網址、等 5 分鐘。
  5. 第一次打開很慢（5–10 秒）免費方案沒人用會休眠，屬正常。若要常駐可考慮付費方案。
