FileFlow · 站台遷移手冊

把站台部署到 Fly.io

照著做就能把 FileFlow 從 Vercel 搬到 Fly.io，繞過資安處的 F-ISAC 網域封鎖。Fly.io 是打指令的，每一行指令都幫你寫好了，複製貼上就行。

預估時間 50–70 分 操作方式 CLI 指令 成功機率 30–40% 費用 需綁卡 · 約 $0–3/月
⚠️

先講白話，別抱太大期望。vercel.app 和 zeabur.app 都已經被 F-ISAC 擋掉了，代表這波掃得很乾淨。fly.dev 只是「比較冷門、可能還沒進名單」，我估成功率 30–40%。這份手冊做完約 1 小時工，就算最後行內連不進去，也等於幫我們確認「免費雲子網域這條路走不通」，下一步就直接走白名單申請 + 綁自有網域（治本）。不算白做。

💳

Fly.io 沒有「不綁卡的免費方案」，這點要先知道。註冊時就會要你填信用卡（會扣約 US$1 驗證，之後退回）。

我們用的規格是 shared-cpu-1x / 512MB，而且在 fly.toml 裡開了 auto stop：沒人用的時候機器會自動關掉、不計費。以你自用的量估，實際帳單大概是 每月 US$0～3。⚠️ 這是我的估算不是保證，建議部署後第一週到 Fly 後台的 Billing 看一次實際數字。

0

開始前，先備齊這四樣

缺一樣就會中途卡住，先確認手邊都有。

  • 一張信用卡 — Fly.io 註冊必填，沒得跳過
  • 能打開 Vercel 後台 — 待會要從這裡把環境變數一個個抄過去
  • 能打開 Google Cloud Console — Drive 上傳的 OAuth 設定要加一條新網址
  • 一支手機，可以開 4G 熱點 — 部署完先用手機（非行內網路）自測功能
📁

程式面我已經弄好了。repo 裡已經有 fly.toml（Fly 的設定檔）和 Dockerfile（建置腳本），你不用改任何程式碼。全程只要在你自己電腦的 PowerShell 裡打指令。

1

安裝 flyctl，註冊帳號

flyctl 是 Fly.io 的指令工具，所有操作都靠它。

  1. 開 PowerShell，貼上這行裝 flyctl 
    pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
    裝完會叫你「重開終端機」，照做，不然打 fly 會說找不到指令。
  2. 重開 PowerShell，確認裝好了 
    fly version
    有印出版本號就是成功。
  3. 註冊帳號（會開瀏覽器） 
    fly auth signup
    選 Sign up with GitHub 最快。註冊流程中會要你填信用卡，填完才能建 app。
    如果你已經有 Fly 帳號，改打 fly auth login。
  4. 切換到專案資料夾 
    cd C:\Users\Alan\Projects\fileuploader
    後面所有指令都要在這個資料夾裡打，因為 Fly 要讀這裡的 fly.toml。
2

建立 app（先不要部署）

這步只是去 Fly 那邊把名字登記起來，還不會真的跑起來。

  1. 執行 launch，但加上「先別部署」 
    fly launch --no-deploy --copy-config --name chb-fileflow --region nrt
    --copy-config = 用我寫好的 fly.toml，不要自作聰明重產一份。
    nrt = 東京機房，離台灣最近。
  2. 它可能會問你要不要開 Postgres / Redis / Tigris全部回 No。我們的 Redis 用的是既有的 Upstash，不需要 Fly 再開一個。
  3. 如果它說「name is already taken」換一個名字重打，例如 chb-fileflow-tw。⚠️ 換名字的話，一定要跟我說，因為 fly.toml 裡有兩處寫死了 chb-fileflow.fly.dev 這個網址，要一起改掉。
🎉

好消息：這次沒有「先有雞還是先有蛋」。Koyeb 那版要先部署才知道網址、再回頭補變數、再重新部署。Fly 的網址是你自己取的名字決定的 —— app 叫 chb-fileflow，網址就一定是 https://chb-fileflow.fly.dev。所以我已經先把它寫進 fly.toml 了，你不用再回填。

3

設定環境變數（Fly 叫它 secrets）

值全部從 Vercel 後台抄。Fly 的 secrets 是加密存的，不會出現在指令紀錄以外的地方。

變數名稱值 / 來源必填
AUTH_SECRET 從 Vercel 抄，務必用同一組，否則已登入的人 session 全失效 必填
REDIS_URL 從 Vercel 抄（rediss://… 開頭） 必填
BREVO_API_KEY 從 Vercel 抄（寄 OTP 信用） 必填
BREVO_SENDER alan0109@mail2000.com.tw 必填
OTP_RECIPIENT alan0109@mail2000.com.tw 必填
GOOGLE_* Vercel 上所有 GOOGLE_ 開頭的變數全部抄過來（Client ID / Secret / refresh token 那組，Drive 上傳用） 必填
NEXT_PUBLIC_APP_URL 不用設！已經寫死在 fly.toml 裡了（除非你 Phase 2 改了 app 名字） 已處理

怎麼設？一行一行打，或一次全打完（推薦）：

# 把「貼上值」三個字換成從 Vercel 抄來的內容，引號要留著
fly secrets set `
  AUTH_SECRET="貼上值" `
  REDIS_URL="貼上值" `
  BREVO_API_KEY="貼上值" `
  BREVO_SENDER="alan0109@mail2000.com.tw" `
  OTP_RECIPIENT="alan0109@mail2000.com.tw"

接著把 GOOGLE_ 開頭那組也設進去（名稱依你 Vercel 上實際的為準）：

fly secrets set `
  GOOGLE_DRIVE_CLIENT_ID="貼上值" `
  GOOGLE_DRIVE_CLIENT_SECRET="貼上值" `
  GOOGLE_DRIVE_REFRESH_TOKEN="貼上值"

設完檢查一下（只會顯示名稱和摘要，不會印出明文，這是正常的）：

fly secrets list
⌨️

那些反引號 ` 是什麼？PowerShell 的「換行接續」符號，讓一行指令可以拆成好幾行比較好讀。如果貼上後報錯，就把它們全刪掉、擠成一行，效果一樣。

📋

怎麼從 Vercel 抄？Vercel 後台 → 選 fileuploader 專案 → Settings → Environment Variables。每條點眼睛圖示顯示明文，複製貼進上面指令的引號中間。

🔑

怎麼分辨哪些是 GOOGLE_ 變數？在 Vercel 環境變數清單裡，名字開頭是 GOOGLE_ 的全部都要（通常有 client id、client secret、refresh token、folder id 之類）。寧可多抄，不要漏。

4

部署

一行指令。Fly 會在雲端照 Dockerfile 建置，不用你電腦裝 Docker。

  1. 執行部署 
    fly deploy --remote-only
    --remote-only = 用 Fly 的雲端機器建置，你本機不需要安裝 Docker Desktop。第一次約 5–10 分鐘。
  2. 看到 1 desired, 1 placed, 1 healthy 就是成功畫面會滾一大堆 build log，那是正常的。
  3. 確認狀態 
    fly status
    State 那欄要是 started，Health checks 要是 1 total, 1 passing。
  4. 你的網址就是： https://chb-fileflow.fly.dev 若 Phase 2 有改過 app 名字，就換成你取的名字。
📜

部署失敗看不懂？打 fly logs 看即時錯誤訊息，把畫面截給我，我幫你判。

5

Google OAuth 加一條重新導向網址

不加這步，登入沒問題，但 Drive 上傳會噴 401。

  1. 開 Google Cloud Console → Credentials
  2. 點開你現在在用的 OAuth 2.0 Client ID就是 Drive 上傳用的那個。
  3. 在「授權的重新導向 URI」按「+ 新增 URI」，貼上： https://chb-fileflow.fly.dev/api/upload/gdrive-token
  4. 存檔。舊的 Vercel 那條不要刪兩邊並存，這樣 Vercel 舊站還能當備援。
⏳

Google 設定有時要幾分鐘才生效。如果剛加完馬上測上傳還是 401，等 5 分鐘再試一次。

6

先用手機 4G 自測（不要用行內網路）

這步是確認「功能本身正常」，跟行內封鎖無關，所以用你自己的網路測。

  1. 手機開 4G / 熱點，開 https://chb-fileflow.fly.dev/login第一次開可能要等 3–5 秒（機器從休眠喚醒），屬正常。
  2. 輸入 email → 收得到 OTP 驗證碼收得到信 = Brevo、Redis 都通了。
  3. 輸入驗證碼登入成功
  4. 傳一個小檔案，確認上傳到 Drive、清單看得到上傳成功 = Google OAuth 那條有生效。
🎯

四項都過，代表整套系統在 Fly.io 上是活的。接下來才是真正的考驗 —— 明天在行內測。

卡住了？對照這裡

  1. fly 不是可辨識的指令flyctl 裝完沒重開終端機。關掉 PowerShell 重開一個再試。
  2. Build 失敗先打 fly logs 看錯在哪。若是記憶體不足（build 被 kill），把 fly.toml 的 memory 暫時改成 1gb 再 deploy 一次。
  3. 網頁開得出來但一直 502 / 轉圈port 對不上。確認 fly.toml 的 internal_port = 8080 跟 Dockerfile 的 EXPOSE 8080 一致（我已經對好了，除非有人改過）。
  4. 登入收不到 OTP 信先 fly secrets list 確認 BREVO_API_KEY、REDIS_URL 有在清單裡；再看 fly logs 有沒有 Redis 連線錯誤。
  5. 能登入但上傳噴 401Google OAuth 重新導向 URI 沒加對，或還沒生效。回 Phase 5 核對網址、等 5 分鐘。
  6. 封鎖警示信裡的按鈕連到 Vercel 舊站NEXT_PUBLIC_APP_URL 沒吃到。這個值是建置時寫進去的，所以改完 fly.toml 要重跑 fly deploy 才會生效，光重啟沒用。
  7. 第一次打開很慢（3–5 秒）機器 auto-stop 後被喚醒，屬正常。要常駐就把 fly.toml 的 min_machines_running 改成 1，但費用會變成固定約 US$2/月。
  8. 不玩了，要停止計費 
    fly apps destroy chb-fileflow
    ⚠️ 這會把 app 整個刪掉，不可復原。確定不用了再打。
