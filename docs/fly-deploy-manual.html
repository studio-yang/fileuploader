FileFlow · 站台遷移手冊

把站台部署到 Fly.io

照著做就能把 FileFlow 從 Vercel 搬到 Fly.io，繞過資安處的 F-ISAC 網域封鎖。Fly.io 是打指令的，每一行指令都幫你寫好了，複製貼上就行。

預估時間 50–70 分 操作方式 CLI 指令 行內可達性 未知 費用 需綁卡 · 約 $2/月
✅

2026-08-06：站台已實際部署完成並驗證通過。網址 https://tdoc-fileflow.fly.dev，health check passing，外部實測 GET /login 回 HTTP 200 · 0.27 秒。

過程中踩到 5 個坑，修正都已進版（Dockerfile + fly.toml，commit 9f80db5）。你如果是照這份手冊重跑一次，那 5 個坑不會再遇到 —— 但排錯區仍保留完整記錄，供日後查因。

⚠️

先講白話，別抱太大期望。vercel.app 和 zeabur.app 都已經被 F-ISAC 擋掉了，代表這波掃得很乾淨。fly.dev 只是「比較冷門、可能還沒進名單」，我估成功率 30–40%。這份手冊做完約 1 小時工，就算最後行內連不進去，也等於幫我們確認「免費雲子網域這條路走不通」，下一步就直接走白名單申請 + 綁自有網域（治本）。不算白做。

💳

Fly.io 沒有「不綁卡的免費方案」，這點要先知道。註冊時就會要你填信用卡（會扣約 US$1 驗證，之後退回）。

規格 shared-cpu-1x / 256MB（東京），24 小時全開的話是 US$2.02/月；但我們開了 auto-stop，閒置時機器會關掉不計費。以上班時段才有人用估算，機器費大約 US$0.5/月（約 NT$16）。

⚠️ 真正會長大的是流量費，不是機器費。東京對外流量 US$0.04/GB 且無免費額度，而 Fly 官方不提供任何支出上限或帳單警示（連預付點數都不是上限，用完直接扣卡）。每月傳 200GB 就是 US$8，1TB 就是 US$40 —— 會隨使用量線性成長且沒有煞車。

⚠️ 因為行內會擋 Drive／GitHub 網域，檔案必須穿過 Fly，這筆流量費省不掉（除非改儲存後端）。請每週到 Fly 後台 Billing 看一次實際數字。

開始前，先備齊這四樣

缺一樣就會中途卡住，先確認手邊都有。

  • 一張信用卡 — Fly.io 註冊必填，沒得跳過
  • 能打開 Vercel 後台 — 待會要從這裡把環境變數一個個抄過去
  • 能打開 Google Cloud Console — Drive 上傳的 OAuth 設定要加一條新網址
  • 一支手機，可以開 4G 熱點 — 部署完先用手機（非行內網路）自測功能
📁

程式面我已經弄好了。repo 裡已經有 fly.toml（Fly 的設定檔）和 Dockerfile（建置腳本），你不用改任何程式碼。全程只要在你自己電腦的 PowerShell 裡打指令。

1

安裝 flyctl，註冊帳號

flyctl 是 Fly.io 的指令工具，所有操作都靠它。

  1. 開 PowerShell，貼上這行裝 flyctl 
    iwr https://fly.io/install.ps1 -useb | iex
    裝完會叫你「重開終端機」，照做，不然打 fly 會說找不到指令。
  2. 重開 PowerShell，確認裝好了 
    fly version
    有印出版本號就是成功。
  3. 註冊帳號（會開瀏覽器） 
    fly auth signup
    選 Sign up with GitHub 最快。註冊流程中會要你填信用卡，填完才能建 app。
    如果你已經有 Fly 帳號，改打 fly auth login。
  4. 切換到專案資料夾 
    cd C:\Users\Alan\Projects\fileuploader
    後面所有指令都要在這個資料夾裡打，因為 Fly 要讀這裡的 fly.toml。
🪟

Fly 官網那行不要照抄。官方文件寫的是 pwsh -Command "iwr …"，pwsh 是 PowerShell 7 的指令。你這台裝的是 Windows 內建的 PowerShell 5.1，照抄會噴「無法辨識 'pwsh' 詞彙」。上面步驟 1 已經把外殼拿掉了，直接用那版即可。

若步驟 1 改噴 TLS / SSL 連線錯誤（PS 5.1 偶發），先跑下面這行升到 TLS 1.2，再重試一次步驟 1：

[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
2

建立 app（先不要部署）

這步只是去 Fly 那邊把名字登記起來，還不會真的跑起來。

  1. 執行 launch，但加上「先別部署」 
    fly launch --no-deploy --copy-config --name tdoc-fileflow --region nrt
    --copy-config = 用我寫好的 fly.toml，不要自作聰明重產一份。
    nrt = 東京機房，離台灣最近。
  2. 它可能會問你要不要開 Postgres / Redis / Tigris全部回 No。我們的 Redis 用的是既有的 Upstash，不需要 Fly 再開一個。
  3. 如果它說「name is already taken」換一個名字重打，例如 tdoc-fileflow-tw。⚠️ 換名字的話，一定要跟我說，因為 fly.toml 裡有兩處寫死了 tdoc-fileflow.fly.dev 這個網址，要一起改掉。
🚫

絕對不要用網頁版的 Launch UI。如果 Fly 把你導到網頁上的「Launch an App from GitHub」畫面，或後台出現「Launch via CLI」按鈕 —— 都不要按。理由有二：

① 網頁流程是從 GitHub 抓程式，而我們的 fly.toml 和修好的 Dockerfile 若還沒 push 上去，它會拿到舊版而失敗。
② 它會覆寫你本機的 fly.toml，把 [build.args] 洗掉，導致警示信連結指向錯誤網址。

網頁上那格 Environment Variables 也不要填 —— 那會以明文寫進 app config，在後台看得到。金鑰一律走 fly secrets set（加密儲存），見 Phase 3。

🎉

好消息：這次沒有「先有雞還是先有蛋」。Koyeb 那版要先部署才知道網址、再回頭補變數、再重新部署。Fly 的網址是你自己取的名字決定的 —— app 叫 tdoc-fileflow，網址就一定是 https://tdoc-fileflow.fly.dev。所以我已經先把它寫進 fly.toml 了，你不用再回填。

3

設定環境變數（Fly 叫它 secrets）

值全部從 Vercel 後台抄。Fly 的 secrets 是加密存的，不會出現在指令紀錄以外的地方。

變數名稱值 / 來源必填
AUTH_SECRET 從 Vercel 抄，務必用同一組，否則已登入的人 session 全失效 必填
REDIS_URL 從 Vercel 抄（rediss://… 開頭） 必填
BREVO_API_KEY 從 Vercel 抄（寄 OTP 信用） 必填
BREVO_SENDER alan0109@mail2000.com.tw 必填
OTP_RECIPIENT alan0109@mail2000.com.tw 必填
GOOGLE_* Vercel 上所有 GOOGLE_ 開頭的變數全部抄過來（Client ID / Secret / refresh token 那組，Drive 上傳用） 必填
NEXT_PUBLIC_APP_URL 不用設！已經寫死在 fly.toml 裡了（除非你 Phase 2 改了 app 名字） 已處理

怎麼設？一行一行打，或一次全打完（推薦）：

# 把「貼上值」三個字換成從 Vercel 抄來的內容，引號要留著
fly secrets set `
  AUTH_SECRET="貼上值" `
  REDIS_URL="貼上值" `
  BREVO_API_KEY="貼上值" `
  BREVO_SENDER="alan0109@mail2000.com.tw" `
  OTP_RECIPIENT="alan0109@mail2000.com.tw"

接著把 GOOGLE_ 開頭那組也設進去（名稱依你 Vercel 上實際的為準）：

fly secrets set `
  GOOGLE_DRIVE_CLIENT_ID="貼上值" `
  GOOGLE_DRIVE_CLIENT_SECRET="貼上值" `
  GOOGLE_DRIVE_REFRESH_TOKEN="貼上值"

設完檢查一下（只會顯示名稱和摘要，不會印出明文，這是正常的）：

fly secrets list
⌨️

那些反引號 ` 是什麼？PowerShell 的「換行接續」符號，讓一行指令可以拆成好幾行比較好讀。如果貼上後報錯，就把它們全刪掉、擠成一行，效果一樣。

📋

怎麼從 Vercel 抄？Vercel 後台 → 選 fileuploader 專案 → Settings → Environment Variables。每條點眼睛圖示顯示明文，複製貼進上面指令的引號中間。

🔑

怎麼分辨哪些是 GOOGLE_ 變數？在 Vercel 環境變數清單裡，名字開頭是 GOOGLE_ 的全部都要（通常有 client id、client secret、refresh token、folder id 之類）。寧可多抄，不要漏。

4

部署

一行指令。Fly 會在雲端照 Dockerfile 建置，不用你電腦裝 Docker。

  1. 執行部署 
    fly deploy --remote-only
    --remote-only = 用 Fly 的雲端機器建置，你本機不需要安裝 Docker Desktop。第一次約 5–10 分鐘。
  2. 看到 1 desired, 1 placed, 1 healthy 就是成功畫面會滾一大堆 build log，那是正常的。
  3. 確認狀態 
    fly status
    State 那欄要是 started，Health checks 要是 1 total, 1 passing。
  4. 你的網址就是： https://tdoc-fileflow.fly.dev 若 Phase 2 有改過 app 名字，就換成你取的名字。
🎭

最重要的一條：CLI 說失敗，不代表真的失敗。實測過程中 fly deploy 有四次回報錯誤，但其中兩次其實已經部署成功了。訊息長這樣：

net/http: request canceled　或　wsarecv: A connection attempt failed…

這是你這台電腦連 api.machines.dev 的網路被中斷，導致 CLI 等不到結果就自己宣告失敗 —— 機器在 Fly 那邊可能已經跑起來了。看到這種訊息，先別重跑部署，改用下面兩條指令查真實狀態：

fly status        # STATE 是 started、CHECKS 是 passing 就是成功了
fly checks list   # 看 health check 實際回傳什麼
📜

真的失敗、但看不懂？打 fly logs 看即時錯誤訊息，把畫面截給我，我幫你判。

5

Google OAuth 加一條重新導向網址

不加這步，登入沒問題，但 Drive 上傳會噴 401。

⏸️

本輪跳過整個 Phase 5。因為 GOOGLE_DRIVE_REFRESH_TOKEN 讀不到、Drive 沒設定，加了重新導向網址也沒用。以下步驟留著，等日後要處理 Drive 時再照做。

  1. 開 Google Cloud Console → Credentials
  2. 點開你現在在用的 OAuth 2.0 Client ID就是 Drive 上傳用的那個。
  3. 在「授權的重新導向 URI」按「+ 新增 URI」，貼上： https://tdoc-fileflow.fly.dev/api/upload/gdrive-token
  4. 存檔。舊的 Vercel 那條不要刪兩邊並存，這樣 Vercel 舊站還能當備援。
⏳

Google 設定有時要幾分鐘才生效。如果剛加完馬上測上傳還是 401，等 5 分鐘再試一次。

6

先用手機 4G 自測（不要用行內網路）

這步是確認「功能本身正常」，跟行內封鎖無關，所以用你自己的網路測。

  1. 手機開 4G / 熱點，開 https://tdoc-fileflow.fly.dev/login機器是常駐的，應該秒開（實測 0.27 秒）。若要等好幾秒，那不正常，跟我說。
  2. 輸入 email → 收得到 OTP 驗證碼收得到信 = Brevo、Redis 都通了。
  3. 輸入驗證碼登入成功登得進去 = AUTH_SECRET、JWT 簽發都正常。
  4. 傳一個小檔案，provider 選 GitHub上傳成功 = GitHub Releases 那條通了。檔案會進 studio-yang/fileuploader 的 fileflow-uploads release。
🔕

Google Drive 這輪不會通，這是刻意的。選 Drive 上傳會噴 HTTP 500 · missing_env —— 因為 GOOGLE_DRIVE_REFRESH_TOKEN 在 Vercel 被設為 Sensitive 讀不出來，我們決定先不重產（那條 token 已經壞過 5 次，為了一個還沒驗證的備援站去動它，風險跟收益不成比例）。

所以 Phase 5 的 Google OAuth 設定這輪也跳過。等行內測試確認這條路可行，再回頭專門處理 Drive。

🎯

先別急著判定「被擋」—— 有第三種可能。實測發現你這台電腦到 Fly 的 IPv6 是不通的（IPv4 打 /login 回 200，IPv6 連不上）。

如果行內網路也這樣，瀏覽器理論上會自動 fallback 到 IPv4，但可能要先等 IPv6 逾時。所以若明天開起來是「轉圈很久」而不是「跳出封鎖頁」，那大概率是 IPv6 問題，不是 F-ISAC。兩者要分清楚，結論完全不同。把畫面截給我判斷。

卡住了？對照這裡

前 5 條是 2026-08-06 首次部署時實際踩到的坑，修正都已進版。

🔴 五個實戰坑（已修好，此處留存原因）

共同點：沒有一個是 Fly.io 的問題，全是這個 app 第一次離開 Vercel serverless 環境才浮現的體質問題。Vercel 幫你擋掉了這些，所以在那邊永遠遇不到。

  1. ① npm ci 失敗：Missing: gaxios@7 … from lock file不是相依性壞掉，是 npm 版本差異。package-lock.json 由本機 npm 11 產生，但 node:20-alpine 內建 npm 10 會解析出不同的相依樹。
    修法：Dockerfile 加 RUN npm install -g npm@11 對齊版本。不動 lock 檔，才不會波及 Vercel 正式站。
  2. ② npm ci 失敗：gyp ERR! find Python相依樹裡的 better-sqlite3 是原生模組，要編譯，但 alpine 沒有 Python 和編譯器。
    它是 mem0ai 帶進來的 —— 而 mem0ai 只有本機的 scripts/mem0-*.mjs 在用，src/ 根本沒 import，卻被放在 dependencies 裡。
    修法：Dockerfile 加 RUN apk add --no-cache python3 make g++。
    治本（未做）：把 mem0ai 移到 devDependencies —— 但那要動 package.json，會影響 Vercel，該另開任務處理。
  3. ③ health check connect: connection refused（第一版）啟動 log 只印 - Local: http://localhost:8080、沒有 Network 那行 = Next.js 只綁在 localhost。
    原因：Fly 會注入 HOSTNAME=<machine-id>，next start 拿它當預設綁定位址，解不出來就退回 localhost。
  4. ④ health check connection refused（第二版，同樣訊息不同病因）加了 -H 0.0.0.0 之後還是refused。SSH 進機器打 netstat -tln 才看到真相：
    tcp 0.0.0.0:8080 LISTEN（Next.js，只有 IPv4）
    tcp fdaa:…:22 LISTEN（SSH，IPv6）
    Fly 內部網路是 IPv6，綁 0.0.0.0 只吃 IPv4，健康檢查一樣打不進來。
    修法：綁 -H ::，Node 雙棧模式 IPv4／IPv6 通吃。⚠️ 這是最隱蔽的一個，錯誤訊息跟 ③ 一模一樣。
  5. ⑤ 「auto-stop 造成 502 死結」—— 這條是誤判，已更正當時的現象是真的（機器停掉後外部一直 502／503），但歸因錯了。我在同一輪部署裡同時改了 IPv6 綁定和關掉 auto-stop，兩件事沒有分開驗證就下結論。
    真因是坑 ④ 的 IPv6 綁定 —— 健康檢查根本連不上 app，跟機器停不停無關。
    2026-08-06 實測更正：IPv6 修好後重新開啟 auto-stop，完全正常。停機後打 /login 回 HTTP 200，冷啟動 10.3 秒（我原本估 33 秒，高估了 3 倍）。
    教訓：一次只改一件事，否則歸因必錯。

⚪ 其他一般狀況

  1. fly deploy 說失敗，但可能是假的看到 net/http: request canceled 或 wsarecv: A connection attempt failed… —— 這是你這台連 api.machines.dev 斷線，不是部署失敗。先跑 fly status 確認，started + passing 就是成功了，別急著重跑。
  2. 「無法辨識 pwsh 詞彙」你抄到 Fly 官網的 PowerShell 7 版指令了。把 pwsh -Command "…" 這層外殼拿掉，只留引號裡面那段，見 Phase 1 步驟 1。
  3. fly 不是可辨識的指令flyctl 裝完沒重開終端機。關掉 PowerShell 重開一個再試。
  4. Build 被 OOM kill把 fly.toml 的 memory 暫時改成 1gb，deploy 完再改回 512mb。
  5. 登入收不到 OTP 信先 fly secrets list 確認 BREVO_API_KEY、REDIS_URL 有在清單裡；再看 fly logs 有沒有 Redis 連線錯誤。
  6. 封鎖警示信裡的按鈕連到 Vercel 舊站NEXT_PUBLIC_APP_URL 沒吃到。這個值是建置時內嵌的，改完 fly.toml 一定要重跑 fly deploy，光 fly machine restart 沒用。
  7. 要看機器裡面到底在跑什麼 
    fly ssh console -C "netstat -tln"
    坑 ④ 就是這樣抓出來的 —— 比看 log 猜測可靠得多。機器要在 started 狀態才連得進去。
  8. 不玩了，要停止計費 
    fly apps destroy tdoc-fileflow
    ⚠️ 這會把 app 整個刪掉，不可復原。確定不用了再打。機器是常駐計費的，確定不用一定要記得刪。
